# 电商运营自动化 Agent：面试与简历指南

这份文档用于帮助项目作者真正讲清楚代码和设计。面试时不要背诵全部内容，应结合自己实际操作过的功能回答。

## 一、60 秒项目介绍

> 我做了一个基于 FastAPI 和千问的电商运营 AI 应用。用户可以输入商品、成本、目标人群和经营目标，系统先用 Python 工具计算真实利润，再把业务信息和计算结果交给大模型生成结构化运营策略。模型返回结果会经过 Pydantic 格式校验和风险表述检查，然后保存到 SQLite，网页可以回放执行过程并收集用户反馈。项目还支持 Excel 批量利润分析和结果导出。我为主要接口、数据库和 AI 调用编写了自动化测试，真实 API Key 使用 `.env` 隔离，没有上传到 GitHub。

## 二、3 分钟技术讲解顺序

按照下面顺序讲，比逐个罗列技术名词更清楚：

1. **业务输入**：商品名称、卖点、目标用户、平台、售价、成本、运费、佣金和经营目标。
2. **参数校验**：FastAPI 接收请求，Pydantic 检查价格范围、文本长度和必填字段。
3. **工具调用**：利润计算服务得出佣金、总成本、单件利润和利润率。
4. **Prompt 构建**：把真实业务输入和工具结果写入 Prompt，并要求模型返回固定 JSON。
5. **模型调用**：通过兼容 Chat Completions 的客户端调用千问。
6. **输出校验**：Pydantic 校验总体判断、定价建议、营销方案、风险提醒和行动计划。
7. **风险检查**：标记绝对化或无法直接核验的营销承诺，提醒人工复核。
8. **数据持久化**：SQLAlchemy 将请求、结果、执行轨迹和用户反馈保存到 SQLite。
9. **网页回放**：前端展示结果、运行耗时和模型调用次数，并允许恢复原始表单。
10. **自动化测试**：使用 Fake AI Client 和临时数据库验证流程，不产生模型费用。

## 三、核心目录怎么讲

```text
app/api/routes/                 HTTP 接口层，负责接收请求和转换错误状态码
app/schemas/                    Pydantic 请求、响应和结构化 AI 输出
app/services/                   利润、Prompt、AI 客户端、Agent 编排和风险检查
app/repositories/               SQLAlchemy 数据访问
app/models/                     SQLite 表模型
app/web/                        中文网页、样式和交互逻辑
tests/                          接口、数据库、服务、启动器和容器配置测试
run_server.py                   自动检测空闲端口的一键启动器
Dockerfile、compose.yaml        可选容器配置；当前未完成真实构建验证
```

回答代码分层问题时，可以说：路由层只处理 HTTP，业务逻辑进入 service，数据库读写进入 repository，数据结构集中放在 schema 和 model 中。

## 四、常见面试问题

### 1. 你的项目为什么叫 Agent？

它不是通用自主智能体，而是面向电商运营场景的可控工作流 Agent。系统会理解业务目标、调用利润工具、调用模型、校验结果并记录执行轨迹。当前使用固定编排，是为了保证流程可解释、可测试和成本可控。

### 2. 为什么利润不直接让大模型计算？

大模型擅长语言生成，但数值计算可能不稳定。利润属于确定性业务规则，应该由 Python 工具计算，再把可信结果交给模型做策略分析。这是工具增强 AI 应用的基本思路。

### 3. 怎么减少模型幻觉？

- 只允许模型基于用户输入和工具计算结果生成内容；
- Prompt 明确禁止编造销量、评价和认证；
- 使用结构化 JSON 输出和 Pydantic 校验；
- 对绝对化营销词进行规则检查；
- 页面提示结果需要人工复核。

不能回答“已经完全消除幻觉”，因为任何生成模型都无法做到这一点。

### 4. 为什么没有直接使用 LangChain？

第一阶段直接实现 Prompt、客户端、工具和编排，是为了理解底层调用链，而不是只会调用框架封装。后续做知识库或多工具路由时，可以再引入 LangChain，并比较框架带来的收益和复杂度。

### 5. API Key 怎么保护？

真实 Key 只写在本地 `.env`，该文件被 `.gitignore` 排除。代码和 `.env.example` 不包含真实值，公开接口只返回是否完成配置，不会返回 Key。

### 6. 为什么使用 SQLite？

当前项目是本地单用户学习和面试演示，SQLite 不需要额外安装，足够验证 ORM、事务和持久化。若进入多用户部署阶段，会迁移到 PostgreSQL，并增加数据库迁移工具。

### 7. 怎么测试收费的 AI 接口？

自动化测试通过依赖覆盖注入 Fake AI Client，返回固定结构化数据。这样可以验证 Agent 流程和异常处理，同时保证测试可重复、不依赖网络、不消耗额度。

### 8. 项目中遇到过什么真实问题？

Windows 上被异常结束的本地服务留下了端口占用，导致 Uvicorn 报 `WinError 10048`。项目后来增加 `run_server.py`，通过实际尝试绑定端口判断是否可用，并自动选择后续空闲端口。这个处理比固定改成 8001 更可靠。

### 9. 为什么删除了自动质量分数？

早期版本根据字段长度和行动数量生成 100 分制评分，但它不能代表策略的真实业务质量，反而增加理解成本。后来删除该功能，保留可解释的风险检查，并增加用户“有帮助/需要改进”反馈。这个决策体现了根据产品价值主动减少无效复杂度。

### 10. 如果继续完善，你会优先做什么？

根据真实使用需求选择，而不是一次加入所有技术：

1. 建立固定业务案例和人工标注，离线比较 Prompt 或模型版本；
2. 保存失败调用、错误类型和耗时，形成基础可观测性；
3. 增加身份认证和数据隔离；
4. 数据库迁移到 PostgreSQL；
5. 根据实际需要决定是否恢复 Docker 环境或进行公网部署。

## 六、现场演示顺序

面试演示控制在 3 到 5 分钟：

1. 运行 `run_server.py`，说明自动端口选择；
2. 打开中文工作台，展示服务状态和当前模型；
3. 提交一条运营 Agent 请求；
4. 指出利润由工具计算，不是模型猜测；
5. 展示结构化策略、执行轨迹、耗时和风险检查；
6. 打开历史记录并提交真实反馈；
7. 简要展示 Excel 批量处理；
8. 打开终端执行 `python -m pytest -q`，说明测试不调用收费模型。

不要在演示过程中展示 `.env`、API Key 或任何包含真实密钥的终端输出。
